2. AWS Cluster Deployment Review
================================
- User asked what must change to deploy the project as a cluster on AWS, including IP addresses.
- Recommendation: use ECS Fargate plus Application Load Balancer plus RDS PostgreSQL unless Kubernetes/EKS is specifically required.
- Backend public URL should move from local/LAN addresses to a stable DNS name such as https://api.your-domain.com.
- Flutter should be built with --dart-define=BACKEND_BASE_URL=https://api.your-domain.com.
- ESP32 firmware should use BACKEND_READINGS_URL=https://api.your-domain.com/api/readings.
- Backend env vars should be set in AWS Secrets Manager, SSM, ECS task env, or Kubernetes Secret, not committed .env files.
- Important env vars: DATABASE_URL, SECRET_KEY, DEVICE_INGEST_TOKEN, CORS_ORIGINS, GEMINI_API_KEY, ECG_MODEL_DIR, MORPHOLOGY_MODEL_DIR, BP_MODEL_DIR.
- Database should be RDS PostgreSQL in private subnets/security groups, not a public database.
- Security groups: public ALB on 443, backend tasks on 8000 only from ALB, RDS on 5432 only from backend.
- AI model artifacts must be baked into the Docker image, mounted from EFS, or downloaded from S3 at startup.
- Cluster warning: the in-memory analysis queue is not durable and each replica has its own worker. For true multi-replica production, split API and worker and use SQS, Redis/Celery, or database-backed jobs.

- Docker build was not run because it would need network pulls for base images and packages.

5. EC2 Deployment Steps
=======================
- User asked what they need to do to deploy backend and AI model on an EC2 instance.
- Recommended EC2: Ubuntu, t3.medium or t3.large, 30-50 GB disk.
- Security group: open SSH 22 only from your IP; open 8000 temporarily for API testing or use 80/443 with nginx; do not expose PostgreSQL publicly.
- Install Docker: sudo apt update; sudo apt install -y docker.io git; sudo systemctl enable docker; sudo systemctl start docker; sudo usermod -aG docker ubuntu; then log out and SSH again.
- Copy project to EC2 by git clone or SCP. Ensure Backend-bisho, AI models, Dockerfile, and .dockerignore are present.
- Create medical.env on EC2 with DATABASE_URL, SECRET_KEY, DEVICE_INGEST_TOKEN, CORS_ORIGINS, GEMINI vars, and RUN_MIGRATIONS=true for first startup.
- Build image: docker build -t medical-backend-ai .
- Run container: docker run -d --name medical-backend --restart unless-stopped --env-file medical.env -p 8000:8000 medical-backend-ai.
- Check logs: docker logs -f medical-backend.
- Test API: curl http://YOUR_EC2_PUBLIC_IP:8000/.
- Hardware URL should become http://YOUR_EC2_PUBLIC_IP:8000/api/readings for temporary testing, or https://api.your-domain.com/api/readings for production.
- Flutter should use --dart-define=BACKEND_BASE_URL=http://YOUR_EC2_PUBLIC_IP:8000 or the HTTPS domain.
- For real production, use HTTPS, a domain, and preferably RDS PostgreSQL rather than a database exposed on the EC2 public network.
